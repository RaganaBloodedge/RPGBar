# 交接：第 0 步重做记录（LLM 判定切分 + 五类容器靶子）

> 2026-10-24。给接手者：这份记录覆盖 **handoff-切分与知识库结构设计.md §6 被推翻后的实际做法**，
> 与 `docs/知识库目标结构.md`（目标数据结构）、`docs/assets/需求隐含的数据结构.svg` 一起看。

## 1. 为什么推翻 §6

§6 的计划是"在**块**上打补丁"：版式启发已经切出了块，再让 LLM 在"疑似多条目"的块上补刀，
再跨页合并。问题是**块本身就不是条目**：COC 的怪物名和说明段同缩进同字号，版式永远认不出；
补刀拿到的还是错的块。实测的证据链：

- 2175 块里 **LLM 只判了 796 块（37%）**，1351 块是词表判的，`report.json` 里连这个数都没有；
- 三胞胎（同页 4 个书签 → 同一段 701 字被切三份）：根因在**章节区间**，不在块；
- 「深潜者 CON=755」：根因是**属性表被当成普通表格**切成 23 字行块（标题就叫 STR），
  抽取器只能猜行归属；
- 「INT/POW 伪实体」：同一根源（行块标题被当成怪物名）。

## 2. 三个硬发现（都不是调参能解决的）

1. **本地 LLM 调用失败的真因是系统代理**：Windows 的 `Internet 选项` 开了 127.0.0.1:7890，
   httpx 的 `trust_env` 把发往 `127.0.0.1:8080` 的请求交给代理，代理回 **502**；
   llama-server 日志里一条请求都没有。上一版 62% 的块因此静默回落规则层。
   修法：`compiler/graph/llm_classify.py::get_default_model` 对 localhost 端点传
   `httpx.Client(trust_env=False)`。
2. **4B 不能在长指令/长窗口上做判定**：8000 字、130 行的窗口 + "把它切成条目"这种抽象指令，
   它会退化成"每行一个条目"（标题还都合法，护栏拦不住）。改成 **短窗口（900–2000 字）+
   按类的成员定义 + 一个样例**，同一个位置（达贡/海德拉、技能列表）就切得干净。
   **所以必须先判类、再按类切**，这是这版最核心的改动。
3. **书签同页必须用页内锚点**：COC 第 77 页挂了 4 个书签（5.7/5.8/智力检定/知识检定），
   只按页码切，四节各自把整页切一遍。`reader.Book.bookmark_anchors` 记书签落点 y，
   `outline.build_sections` 用"页 + 页内阅读顺序行号"给每节划互不重叠的区间。

## 3. 新架构：三层分工

```
几何（规则算）   阅读顺序 / 页内锚点 / 表格网格 / 原文偏移 / 行号     —— 不做任何语义判断
判定（LLM 做）   这一节是什么类 → 条目边界在哪 → 这块是哪一类/是否示例
验收（规则做）   行号合法递增 / 标题逐字来自行首 / 按行拼回无损 / 不许逐行切
```

**失败不回落**：LLM 拿不到意见 → 退避重试 → 拆批重问 → 仍失败才中止编译。
分类阶段缺一块就抛错，绝不用词表顶（旧版就是靠"静默回落"活着，报告里还看不出来）。

## 4. 代码地图

## 5. 跑法

```bash
# 引擎（单槽是硬要求：多槽会把 16384 切成每槽几 k，超长批整批失败）
cd tools/src/llama.cpp-b11819/build/bin
./llama-server.exe -m ../../../models/Qwen3-4B-Q4_K_M.gguf -ngl 99 -c 16384 \
  --parallel 1 --port 8080 --reasoning-budget 0 --no-webui

# 编译
RPGBAR_LLM="qwen3-4b@http://127.0.0.1:8080/v1|sk-local" \
  python -m compiler.cli graph --pdf <书.pdf> --out data/kb/coc7e-v2 --book-id coc7e-v2 --use-llm

# 验收
python scripts/kb_acceptance.py --kb data/kb/coc7e-v2/kb.sqlite
python scripts/kb_audit.py --kb data/kb/coc7e-v2/kb.sqlite
```

- 切分结果按节缓存在 `data/kb/<book>/_seg_cache/`：重跑只补没切过的节。
- 离线（`--use-llm` 不带）走 `_split_by_layout`，那是**测试路径**，不是生产路径。

## 6. 已知限制（下一步要解决）

1. **lore 的摘要聚类还没做**：现在 lore 块是散的，`lore_topic/lore_member` 两张表还空着。
2. **五类容器没有物化**：`rule_subtype/rule_flow/pc_skill/item/npc` 这些表已在
   `docs/知识库目标结构.md` 定义，但还没有编译器去填；现在跑出来的是"块 + 通用实体/事实"。
3. **4B 的判类会漂**：少数节被判成相邻类（如技能列表里的规则段被当 pc），
   容器编译器要按"块的实际内容"二次取材，不能只信节类。
4. **窗口内的跨页续接**靠 `open_tail` 协议 + 窗口缩小兜底；极端版式仍会出现
   "一条被切成两段"（title 重复，可查 `_seg_cache`）。

## 8. 这一轮修掉的五个真 bug（都会让结果"看起来正常但其实是错的"）

1. **系统代理 502** → 上一版 62% 的块没问过模型。
2. **书签同页只按页码切** → 三胞胎。
3. **属性表 y 坐标跨页比较**（`_pos_index` 没带页码）→ 26 张怪物属性表全挂到第一节上。
4. **多窗口行号没加偏移** → 怪物图鉴 32 页被压成一条 2255 行巨块。
5. **自检/合并不按类** → 技能列表被当逐行切、怪物的小标题被切成独立条目。

## 9. 还没做（下一轮）

1. **五类容器物化**：`rule_subtype/rule_flow/pc_skill/item/npc` 还没有编译器去填。
2. **unclassified 6.9%**：主要是证据没逐字命中（被判废进 disputed.json），
   需要按类给 few-shot 证据示例，而不是放宽护栏。
3. **NPC 名字噪声**：少量怪物实体叫"躲避""咬住"（属性表归位到动作行），
   需要"名字行必须不像动作/结构词"的成员形状检查。
4. **llm_extract 的 JSON 失败率 ~48%**：extract 的 schema 太大，4B 输出常被截断；
   应改成"先问有哪些实体，再逐个问字段"的两段式。

五类容器已经落地为**可查的产物表**（`compiler/containers.py` + `python -m compiler.cli containers`），
每次全量编译的 `index → containers → report` 也会自动生成。

| 容器 | 产物（data/kb/coc7e-v3） |

| NPC | **30 只怪物**，441 条属性（STR 65 / CON 65 / SIZ 50 … 带掷骰），208 条能力（每回合攻击/战斗方式/护甲/理智丧失/法术） |

判定/拼装的分工：子类名、判定步骤、世界观摘要是**模型判**（引文不在原文的步骤直接丢）；
技能/物品/NPC 档案是从已有 `fact/field` **投影**出来的，不让模型重说一遍；流程图由判定步骤**拼**。

已知问题（下一轮）：
1. 规则子类里"其他"还有 150 条（4B 对无章节归属的规则倾向扔进兜底）；
2. 技能描述带上了邻近技能的文本（实体→块的锚定仍偏粗）；
3. 世界观主题名会重复（同一专名在多个章各成一个主题），需要按名字合并；
4. NPC 里没有人（这本书的 NPC 都是怪物；人类 NPC 要靠 llm_extract，而它还不稳）。

## 11. 第三轮：把阶段二收口（两段式抽取 / 世界观主题 / 容器查询）

### 11.1 两段式实体抽取（替换旧的一次性 extract）

旧 schema 同时要"实体+字段"，4B 的输出近一半是截断的 JSON（一次全量跑 34 分钟、判废 48%）。
现在拆成两段：**先问"这条原文里有哪些能被查的实体"（输出短），再把这些实体名喂回去问字段**。

- 结果：218 块 → 136 实体 / 34 字段，5 分钟；人类 NPC 从 0 变成 **25 个**
  （哈维·沃尔特、帕金·维瑟、道尔顿博士…）。
- 两条**通用**过滤（不靠词表）：章节编号式名字（`1.2 合作与竞争`）不是实体；
  出现在全书 >3% 块里的名字（`调查员`/`守秘人`）是称谓，不是实体。

### 11.2 世界观容器改成"节 = 主题"

按向量全局聚类产出 211 个主题、名字重复、摘要与成员对不上（"克苏鲁"下挂着模组建议）。
现在：**主题 = 一节的 lore 内容**，主题名用节标题（书自己的结构），摘要由模型读这一节写，
并加了一条**跑题护栏**（摘要的三字片段在原文里命中率 <20% 就退回原文摘要）。

- 62 个主题 / 280 段原文 / 25 个多段主题；"表Ⅺ：神话典籍"挂 61 段、"神话典籍译名对照表" 46 段。

### 11.3 容器查询（DM 侧）

`compiler/retrieve.py` 新增 `item_card / skill_card / npc_card / rule_card / lore_topics`：
优先查五类产物表，旧库没有这些表时回落到通用实体层。`python -m compiler.cli demo --kb …`
会把五类各查一条打出来（自证"DM 能不能直接拿到成品"）。

实测（coc7e-v3）：
- `kb.item('加利尔突击步枪')` → 伤害加值 2D6 / 射程 110 / 每轮弹数 1(2)或全自动 / 价格 2000 / 故障 98
- `kb.skill('考古学')` → 基础值 01% + 描述
- `kb.npc('深潜者')` → 11 条属性（STR 65 (2D6+6×5)…）+ 4 条能力（每回合攻击/战斗方式/护甲/理智丧失…）
- `kb.rule('对抗检定')` → 子类"技能检定" + 判定步骤 + 流程图
- `kb.lore('克苏鲁')` → 主题 + 摘要 + 成员原文（带相似度）

### 11.4 仍然没解决的

1. **判定步骤的稳定性**：同一条规则两次抽出来的步骤数会变（4 ↔ 1），4B 对长规则的引文
   经常抄不全，被护栏拒掉后步骤就少了。下一步：按"步骤块"而不是整条规则喂模型。
2. **规则子类里的"其他"** 仍然占 150/353；无章节归属的规则缺少命名线索。
3. **世界观摘要**在"表/清单"型小节上会退化成片段（模型写不出，护栏退回原文摘要）。
4. **技能描述**在"一行一技能"的清单块里只有名字行（这本书的版式就是这样，没错，
   但想要更丰富的描述得靠 llm_extract 给技能补 fact）。

## 12. 第四轮：关系图（五类容器最后一块）

`pc_relation` 以前只有 1 条种子边（正则只能覆盖"是…的…"）。现在 `build_relations`：

1. **候选筛选（几何）**：一段里同时出现 ≥2 个已认出的人/怪名才算候选（248 段）；
2. **判断（模型）**：读原文抽"谁和谁、什么关系、原文哪一句"；关系词 2–6 字（父子/夫妻/主仆/同僚/敌对/侍奉/崇拜/创造/召唤/附身…）；
3. **验收（规则）**：两端必须是候选名；**引文必须同时提到两端**（否则就是脑补）；引文逐字回原文；
4. 通用称谓（"调查员""守秘人"，出现在 >3% 块里）不当节点。

实测 32 条，质量抽样：

```
伍德福德 → 道尔顿博士（同僚）｜"伍德福德和道尔顿博士判定为不可破译的"
黄衣之王 → 哈斯塔（化身）｜"黄衣之王是不可直呼名讳的哈斯塔最常见的化身"
奥古斯特 → 雅各布（同僚）｜"如果奥古斯特或雅各布在场，且棺材被发现了"
法伦 → 莱特（同僚）｜"法伦可以为调查员提供莱特办公室以及房子的钥匙"
```

仍然会错的地方：模型会把"被统治的"说反（克图格亚 ↔ 炎之精），也会把"提供钥匙"读成"同僚"。
这一层只能给 DM 当**线索**，不能当事实断言 —— 它和 npc/物品那种"值+原文"的字段不一样。

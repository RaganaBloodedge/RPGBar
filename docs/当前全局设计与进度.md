# RPGBar 当前全局设计与进度

更新时间：2026-10-28（Asia/Shanghai）

这份文档是当前开发基线。后续实现必须先检查这里的边界，再修改具体模块。

## 目标

RPGBar 是一个剧本无关的本地 Agent DM 引擎：

```text
模型负责理解和表达
服务端负责规则、状态和事实
切分器负责提供剧本知识与可用机制
事件负责连接状态、记忆、叙事和测试
```

## 四个核心对象

### PlayDefinition

玩家选择的是玩法入口，不是孤立文件。

- `mode=sandbox`：规则库驱动，Session Zero 动态生成开局；
- `mode=scenario`：已切分的固定冒险，按场景图推进；
- `rules`：规则档案来源和公开描述；
- `knowledge`：切分器和知识库来源；
- `generation_policy`：开局生成方式；
- `content_ref`：固定内容来源，沙盒可以为空。

代码入口：`server/play_definition.py`。

### RuleProfile / RuleBinding

规则必须按 PlayDefinition 绑定：

- CoC 沙盒绑定 CoC 知识库和 d100 规则档案；
- 没有规则库的固定冒险使用明确的通用 d20 fallback；
- 不允许从全局活动剧本继承规则。

### ScriptKnowledge

切分器产生的静态知识：

- 场景、出口、检定、flag；
- NPC 和物品容器；
- `pc_card_schema`；
- `pc_relation` 静态关系图；
- 规则条目和流程图。

它不保存本局动态状态。

### FactEvent

所有真实变化必须成为服务端事实事件，再更新：

- WorldState；
- World SQLite；
- Chronicle；
- 广播；
- 测试记录。

当前 `GameState.commit_event()` 已覆盖场景、检定、flag、实体、时间、线索和关系事件，但 World 写入仍有部分操作先写库后提交事件，后续需要事务化收口。

## 当前运行链

```text
玩家发言
  ↓
上下文组装
  ↓
ActionJudgeAgent：只理解行动意图
  ↓
Deterministic Validator：验证当前玩法是否允许
  ↓
FactEvent Commit：提交唯一事实
  ↓
NarratorAgent：只解释已确认事实
  ↓
Risk NarrationVerifier：只审查高风险旁白
  ↓
广播 + Chronicle + 测试记录
```

## 已完成

- 本地 4B 模型和 GPU 后端；
- 动态选择剧本，不默认加载蛇王墓；
- CoC 沙盒 Session Zero；
- 固定冒险与 CoC 规则隔离；
- `pc_relation` 静态关系图接入运行时；
- World 动态关系事件；
- 角色卡 Agent 判断和服务端校验；
- ActionJudge 初版；
- 运行时已移除按固定中文动词表判断越界的旧路径；当前行动边界由
  `ActionJudge → action_validation` 根据玩法提供的场景候选和结构化状态决定；
  Narrator 只消费已确认的 blocked 结果，不再按某个剧本的词汇硬编码；
- NarrationVerifier；
- Chronicle 时序检索；
- 状态感知验收器；
- 统一 `PlayDefinition` 第一版。

## 尚未收口

1. `PlayDefinition` 仍需完整接管房间、Session Zero、角色卡和知识库创建流程；
2. ActionJudge 仍需在真实本地模型上继续校准置信度和歧义行为；
3. World 写入和 FactEvent 还不是同一事务；
4. 编译器的 `pc_relation`、`entity_state`、`timeline_event` 还没有统一运行时适配器；
5. 测试器目前只部分支持当前实体、出口和检定的状态感知；
6. 最近一次完整 25 轮新版本验收尚未完成，不能用旧报告代替；
7. 评估 Agent 仍需要人工失败样例校准。

## 开发顺序

1. 统一 PlayDefinition 与规则、知识库、角色卡、Session Zero 的绑定；
2. 统一 ScriptKnowledge 运行时适配器；
3. 收拢 ActionJudge 和 Deterministic Validator，逐步移除旧的重复裁定路径；
4. 让所有 World 写操作通过 FactEvent 事务提交；
5. 更新状态感知测试集和语义评估；
6. 用同一套 25 轮和跨玩法实验验收；
7. 只有测试结果证明架构改动有效后，才继续调整模型提示词。

## 约束

- 不使用 LangChain 或 LangGraph；
- 不按某个剧本写服务端分支；
- 不把关键词表当通用规则；
- Agent 不得直接改事实；
- 旁白不得成为事实来源；
- 角色卡是否需要由 Agent 根据玩法和规则证据判断；
- 规则、状态、事实和记忆必须可回放、可测试、可追溯。

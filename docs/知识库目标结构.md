# 知识库目标结构（从原始需求反推出的数据结构）

> 2026-10-24。这份文档把用户口述的五类需求**翻译成可落库的结构**，是编译器的靶子；
> 与 `docs/assets/需求隐含的数据结构.svg` 一一对应。凡与本文件冲突的实现，以本文件为准。

## 0. 一句话

**五类不是五个标签，是五个容器；每个容器有自己的子结构、自己的成员单位、自己的出口产物。**
`物品`、`属性`、`技能`、`怪物/人` 都是容器**内部的成员类型**（子集），不是与五类并列的东西。

```
原文证据层（块）──► 五类容器 ──► 运行时产物（DM 能直接查的东西）
      ▲                                  │
      └──────── RAG + BM25 回到原文 ◄─────┘
```

## 1. 分层与表

### L0 证据层（原文）
| 表 | 内容 | 说明 |
|---|---|---|
| `source_page` | 逐页原文（阅读顺序） | 一切引用的最终出处 |
| `block` | 证据窗口：`title/text/page/src_start/src_end/kind/canonical` | **块不是条目**，是"可回指的原文片段"；RAG/BM25 与 fact.quote 都指向它 |
| `block_fts` / `block_vec` | BM25 / 向量 | 跨类检索用，不承担状态 |

### L1 章节层（粗分）
`section(id, parent_id, level, title, path, page_start, page_end, anchor_y, end_page, end_y)`
—— 目录/大标题 → 章节树；同一页多个书签用**页内锚点 y** 切成互不重叠的行区间。

### L2 五类容器

#### ① 规则类 `rule`
| 表 | 字段 | 出口产物 |
|---|---|---|
| `rule_entry` | id / block_id / title / subtype_id / text | 规则原文（可引） |
| `rule_subtype` | id / name / parent_id / evidence | **子类树**：战斗先立一档，见到新领域就并行加一档（不预设词表） |
| `rule_step` | rule_id / seq / kind(step|branch|outcome) / text / quote | 判定步骤（流程图的数据源） |
| `rule_flow` | rule_id / nodes / edges | **流程图**（由 rule_step 生成；先能走通，再画图） |

#### ② 玩家属性类 `pc`
| 表 | 字段 | 出口产物 |
|---|---|---|
| `pc_attribute` | entry_id / key(理智/力量…) / label / value / unit / quote | **状态子类** → 角色卡 |
| `pc_card_schema` | field_key / label / kind / order / evidence | **角色卡模板**（字段从书里学出来，不写死 CoC） |
| `pc_skill` | id / name / base_value / description / block_id | **技能直查**：玩家声明"我用侦查"→ 直接命中 |
| `pc_relation` | id / src / dst / rel / evidence_block | **关系图**种子边（明示关系句）；运行期由互动增长 |

#### ③ 工具类 `tool`（物品是其子集）
| 表 | 字段 | 出口产物 |
|---|---|---|
| `item` | id / name / name_norm / aliases / summary / block_id | **名字索引**：名 → 简介，DM 按名直读 |
| `item_field` | item_id / key(价格/伤害/射程…) / value / unit / quote | 物品属性（列名即字段） |

#### ④ NPC 类 `npc`（只读）
| 表 | 字段 | 出口产物 |
|---|---|---|
| `npc` | id / etype(monster|human) / name / aliases / summary / block_id / readonly=1 | **怪物 / 人 两分**，各自档案 |
| `npc_field` | npc_id / key(STR/护甲/理智损失…) / value / dice / quote | 属性与能力（值必须能回指原文） |
| `npc_ability` | npc_id / name / text / quote | 特殊能力 / 法术 / 攻击方式 |
| `entity_state` | campaign_id / npc_id / status(alive|dead|gone|hostile) | **运行期状态**，与只读档案分表 —— 状态不是知识 |

#### ⑤ 常识与世界观 `lore`
| 表 | 字段 | 出口产物 |
|---|---|---|
| `lore_topic` | id / summary / block_id | **先摘要**（主题节点） |
| `lore_member` | topic_id / block_id / similarity / added_at | **相似原文挂在同一摘要下**；每个成员保留原文与出处 |

### L3 检索
`block_fts`（BM25）+ `block_vec`（向量）+ 每条 fact 的 `quote` → **任何一条结论都能回到原文**。
检索按类路由（查技能≠查怪物），但**原文始终可达**。

## 2. 成员单位 = 切分单位（这是切分器唯一该关心的事）

| 容器 | 一个成员长什么样 | 切分锚点（从书里认，不预设） |
|---|---|---|
| rule | 一条规则 / 一个判定点 | 编号步骤、条件句、掷骰表达式、章节归属 |
| pc | 一个属性组 / 一条技能 / 一条关系 | `力量（STR）`、`技能名（NN%）`、`A 是 B 的…` |
| tool | 一件物品 | 清单行 `名称，价格`、表格行 `名称+价格/伤害` |
| npc | 一只怪 / 一个人 | 名字行（**常与描述同行**）+ `属性|平均|掷骰` 表 |
| lore | 一个主题 | 叙述性段落（句读密度、无属性块、无价格） |

**同一个块可以服务多个容器**（怪物条目里的战斗流程既是 npc 的能力，也是 rule 的判定）：
切分只保证"成员边界"，归属由各容器编译器按自己的 schema 取材。

## 3. 分工（Agent 工程）

```
几何（规则算）        阅读顺序 / 页内锚点 / 表格网格 / 原文偏移     —— 不做判定
判定（LLM 做）        这条边界在哪 / 这是哪一类 / 这段是不是示例     —— 唯一判定者
验收（规则做）        切点合法、按行拼回无损、证据逐字可回指         —— 不是第二判定者
```

三条硬约束：

1. **不许回落**：LLM 调用失败/输出非法 → 重试（退避+拆批），仍失败就**中止编译**。
   绝不把"词表判的库"伪装成"模型判的库"。
2. **判源必须可见**：报告首屏写清"每块由谁判"；覆盖率不达标 = 编译失败。
3. **一切结论带证据**：每条 fact/字段都要能 `quote → block → source_page` 回指。

## 4. 与旧实现的差距（已知、已验证）

| 旧实现 | 后果 | 现在 |
|---|---|---|
| 章节只按页码 | 第 77 页挂 4 个书签 → 同段被切 3 份（三胞胎） | 页内锚点 + 行区间 |
| 怪物属性表当普通表格 | 228 个 23 字行块（标题 STR/CON）→ INT/POW 伪实体、CON=755 | 属性表并回条目块（`meta.statblock`） |
| 块 = 段落，分类 = 块级单标签 | 怪物条目被拆成"描述块 + 属性块"两张皮 | 按类切"成员"，容器各自取材 |
| LLM 调用失败静默回落规则 | 62% 的块其实是规则判的，报告里看不出来 | 失败即中止 + 判源进报告 |
| 系统代理截走本地请求 | 表现为"模型调用失败"（502） | 本地端点 `trust_env=False` |

> 各版本变更见 [CHANGELOG.md](../CHANGELOG.md)；服务器启动横幅、`GET /api/version` 与网页顶栏都会显示当前版本号。

## 一、项目概述

RPGBar 是一款**多人联机文字跑团（TRPG）**游戏：一个 AI Agent 担任地下城主（DM），用 RAG 技术约束 DM 严格遵循剧本推进剧情；多名玩家通过浏览器连接服务器实时联机，各自可以召唤「小助手」草拟行动，骰子由服务端统一投掷。

**核心特点**

| 特点 | 说明 |
| --- | --- |
| Agent 当 DM | DM 负责叙事、裁定检定、推进剧情 |
| RAG 守剧本 | 检索剧本相关片段注入 DM，约束它不跑偏 |
| 剧情状态机 | 章节→场景→节拍，flag / 出口 / 检定门控 |
| 多人联机 | WebSocket 房间，多玩家实时同步 |
| 服务端权威骰子 | 玩家只发意图，结果由主机投掷（防作弊） |
| 云/本地双路径 | DM 可走云 API，也可走玩家本地 llama.cpp |
| 可中途加入 | 对局进行中也能加入，DM 自动补剧情 |

**当前形态**：Web 联机 demo。服务器是独立进程，跑在某个玩家（主机）的电脑上，其他玩家连进来一起玩。后续移植 Unity。

## 二、已实现功能清单

1. **多人联机房间**：按房间码隔离，玩家加入/离开实时广播，状态全量同步。
2. **Agent DM 编排**：处理玩家行动的完整流水线（检定 → 出口 → 自由发挥）。
3. **RAG 剧本检索**：jieba 分词 + BM25，检索与当前行动最相关的场景片段。
4. **剧情状态机**：场景推进、flag 门控、出口条件、检定触发。
5. **服务端权威骰子**：d20 检定 + 自由掷骰，支持设种子复现。
6. **小助手建议**：给玩家生成可执行行动建议（玩家的私有 Agent 雏形）。
7. **守剧本护栏**：LLM 只提案 `move_to` / `set_flags`，服务端校验后应用。
8. **脚本化兜底**：无大模型 key 时，DM 用剧本原文 + 提示引导，玩法完整可玩。
9. **样例剧本**：《古堡秘宝》，5 场景、2 NPC、多条检定与 flag 分支。
10. **中途加入 + DM 补剧情**：任何时刻凭房间码加入既有对局；DM 自动生成带入旁白（老玩家同步可见），并给新玩家一份私有的「故事回顾」。
11. **一键启动**：`start.bat`（Windows）/ `start.sh`（Linux/macOS）。
12. **自动化测试**：37 项冒烟测试（进程内确定性 + 实时联机 + 实时中途加入）。

## 三、系统架构

```
┌─────────────────────────┐         ┌──────────────────────────────┐
│      玩家客户端（网页）    │         │     服务器（主机玩家电脑）       │
│                         │  WebSocket │                              │
│  旁白流 / 掷骰 / 输入     │ ◄────────► │  FastAPI + WebSocket 房间      │
│  小助手建议按钮           │   join     │  ├─ DM 编排（叙事/裁定/推进）   │
│  （未来：本地 3B/4B 模型）│  action   │  ├─ RAG 检索（jieba+BM25）     │
│                         │  suggest  │  ├─ 剧情状态机（场景/flag/出口）  │
│                         │  roll     │  ├─ 服务端骰子                 │
└─────────────────────────┘           │  └─ LLM Provider（云/本地）    │
                                      └──────────────────────────────┘
```

- **服务器**（`server/`）：独立进程，承载所有权威逻辑。玩家**不自己起服务**，只连服务器。
- **客户端**（`web/`）：纯静态网页，通过同源 WebSocket 连接服务器。
- **中途加入**：房间在新玩家加入前若已开局，服务器广播 DM 的带入旁白（全员可见），并向该玩家单独推送 `recap`（私有回顾，不打扰其他人）。

### 目录结构

| 路径 | 说明 |
| --- | --- |
| `server/main.py` | FastAPI + WebSocket 房间服务（入口） |
| `server/dm.py` | DM 编排：检定/出口/自由发挥 + 护栏 |
| `server/rag.py` | 剧本加载 + jieba/BM25 检索 |
| `server/state_machine.py` | 场景/flag/出口/检定的权威状态 |
| `server/dice.py` | 服务端骰子（可复现） |
| `server/llm.py` | OpenAI 兼容 Provider（云/本地同套） |
| `server/config.py` | 配置加载 |
| `web/` | 玩家客户端（HTML/CSS/JS） |
| `scripts/sample_script.json` | 样例剧本《古堡秘宝》 |
| `scripts/smoke_test.py` | 冒烟测试 |
| `start.bat` / `start.sh` | 一键启动脚本 |

## 四、快速开始

### 4.1 环境要求

- Python 3.10+
- 能访问同一网络（局域网）或多台能互通的机器

### 4.2 启动服务器（主机玩家）

```bash
pip install -r requirements.txt
python -m server.main
```

或 Windows 直接双击 `start.bat`。启动后终端会打印：

```
[RPGBar] 服务器监听 0.0.0.0:8000
[RPGBar] 本机访问: http://127.0.0.1:8000
[RPGBar] 局域网访问（发给朋友）: http://192.168.x.x:8000
```

### 4.3 玩家加入

把「局域网访问」地址发给朋友，对方浏览器打开即可：

1. 输入名字 + 选择职业（战士/法师/游侠/盗贼）
2. 房间码留空自动建房，或输入朋友的房间码加入
3. 进入游戏，开始跑团

> **跨网络**：不同网络的朋友要连你，需要给服务器电脑做公网映射 / 内网穿透（frp、cpolar 等），或把服务器部署到云主机。

## 五、玩法指南

### 5.1 界面

- **左侧**：旁白/对话流（DM 旁白金色、玩家行动蓝色、骰子结果绿色/红色、系统提示居中）
- **右侧**：队伍成员、已获得的线索（flag）、自由掷骰
- **底部**：行动输入框 + 「助手建议」按钮 + 发送

### 5.2 行动

在输入框描述你的行动，回车发送。例如：

- `说服老周` —— 触发「魅力」检定
- `调查挂毯` —— 触发「调查」检定
- `推开铁门进入门厅` —— 移动场景
- `我四处张望` —— 自由发挥，由 DM 即兴旁白

### 5.3 骰子与检定

- 检定：当你做出对应行动（如说服、调查、战斗）时，DM 自动投 d20，与难度 DC 比较，成功/失败各有剧本写好的结果，并广播给所有人。
- 自由掷骰：点右侧「掷 d20」按钮，纯娱乐。
- 骰子在**服务端**投掷，玩家无法作弊。

### 5.4 小助手建议

点「助手建议」，会基于当前场景给出 3 个可执行建议，点击即发送。这是「玩家的私有 Agent」的雏形——未来会下沉到玩家本地的小模型（3B/4B）。

### 5.5 线索（flag）与分支

成功完成某些检定会获得线索（如 `found_secret_door` 发现暗门），右侧「已获得线索」会列出。这些 flag 用于解锁后续出口，形成分支剧情。

侧栏显示的是 flag 的中文描述（在剧本的 `flags` 段里定义），新玩家看回顾时也是这些描述，比 `has_key` 这样的内部名友好得多。

### 5.6 中途加入

**任何时刻都能加入**——对局进行到一半，朋友打开链接、填上房间码即可，不需要重启房间或等人齐。

加入时会发生两件事：

1. **全员可见的带入旁白**：DM 会写一段话，让新角色自然地登场，并顺带复述此前的关键进展。老玩家也能看到，所以剧情上是连贯的（"一个人推门进来了"），不会突兀。
2. **新玩家私有的「故事回顾」面板**：一张卡片，分三行给出
   - **行程**：走过的场景链（如 `古堡大门 → 门厅`）
   - **线索**：队伍已获得的 flag 中文描述
   - **最近动态**：最近若干条玩家行动记录

三种情况都不会触发补课（按正常加入处理）：房间刚建、只有一个人且什么都没做、或者房间已经空了重开一局。

> 补课内容由 DM 生成：配了 LLM 就由模型写（受「不剧透内幕、不编造剧本外内容」约束），没配就由服务端拼接行程 + 线索 + 当前场景原文——两种情况下信息量都不缺。

## 六、DM 与剧本

### 6.1 DM 如何守剧本

DM 处理玩家行动分三步：

1. **匹配检定**：命中某个检定 → 服务端投骰 → 应用剧本写好的成功/失败结果。
2. **匹配出口**：命中某个出口 → 校验 flag 条件，满足则推进场景，不满足则提示「还做不到」。
3. **自由发挥**：其余交给 LLM 叙事（注入 RAG 检索到的剧本片段）；LLM 可提案推进场景/设 flag，但**必须落在剧本已知的出口与 flag 白名单内**，服务端校验后才生效。

匹配采用「命中关键词数 + 最长命中长度」打分，避免「进入/进去」这类泛化词误配。

### 6.2 剧本格式

剧本是结构化 JSON（`scripts/sample_script.json`），结构如下：

```json
{
  "title": "古堡秘宝",
  "system": "DM 的人设与规则说明（拼进系统提示词）",
  "start_scene": "gate",
  "flags": {
    "knows_backdoor_key": "从老周口中打听到后门钥匙藏在内院枯井旁",
    "has_key": "取得了开启密室后门的钥匙"
  },
  "scenes": [
    {
      "id": "gate",
      "chapter": 1,
      "title": "古堡大门",
      "location": "古堡正门外",
      "public_text": "给玩家看的旁白",
      "dm_notes": "只有 DM 知道的内幕",
      "npcs": [{"name": "老周", "role": "看守", "style": "胆小", "knows": "后门钥匙在井旁"}],
      "keywords": ["大门", "铁门", "古堡"],
      "flags_required": [],
      "flags_set": [],
      "checks": [
        {
          "id": "persuade_zhou",
          "skill": "魅力",
          "dc": 12,
          "keywords": ["说服", "套话", "老周"],
          "success": "成功时的旁白",
          "fail": "失败时的旁白",
          "success_flag": "knows_backdoor_key"
        }
      ],
      "exits": [
        {"to": "hall", "label": "推开铁门进入门厅", "keywords": ["铁门", "门厅"], "condition": null}
      ]
    }
  ]
}
```

**字段说明**

| 字段 | 说明 |
| --- | --- |
| `title` / `system` / `start_scene` | 剧本名 / DM 人设 / 起始场景 id |
| `flags` | flag 的中文描述表：`{flag 名: 一句人话}`，用于侧栏线索与新人回顾 |
| `scenes[].id` | 场景唯一标识 |
| `public_text` | 玩家可见旁白（进入场景时广播） |
| `dm_notes` | 仅 DM 可见的内幕/暗线（RAG 注入，但不直接播给玩家） |
| `npcs[]` | NPC 卡：名字/身份/说话风格/知道什么 |
| `keywords[]` | 检索与匹配用的关键词 |
| `flags_required` | 进入该场景需满足的 flag |
| `flags_set` | 进入场景时自动设置的 flag |
| `checks[]` | 检定：技能、难度 DC、触发关键词、成功/失败文案、成功奖励的 flag |
| `exits[].condition` | 出口可用条件：`null` 恒可用，或填 flag 名（拥有该 flag 才可用） |

### 6.3 如何写新剧本

1. 复制 `scripts/sample_script.json`，改名。
2. 改 `title`、`system`、`start_scene`，编写各 `scenes`。
3. 在 `flags` 段里给每个 flag 写一句中文描述（不写也能跑，只是侧栏和回顾会显示 flag 内部名）。
4. 修改 `server/main.py` 里加载的剧本路径（`ScriptStore(...)` 的参数）。

> flag 白名单**不需要手动维护**：服务端会从剧本里（`flags` 段 + 各场景的 `flags_set` / `flags_required` / `checks[].success_flag`）自动收集合法 flag，LLM 只能设置这些。

## 七、接入大模型

DM 使用 OpenAI 兼容接口，**云 API 与本地 llama.cpp 共用同一套 Provider**。

### 7.1 云 API（开发/体验推荐）

```bash
export RPGBAR_LLM_API_KEY="sk-xxx"
export RPGBAR_LLM_BASE_URL="https://api.deepseek.com/v1"
export RPGBAR_LLM_MODEL="deepseek-chat"
```

DeepSeek / 智谱 GLM / 通义 Qwen 均兼容，改 `base_url` + `model` 即可。

### 7.2 本地 llama.cpp（发布到玩家 PC 的关键）

```bash
# 1. 玩家自己的机器启动 llama.cpp server
llama-server -m qwen3-8b.Q4_K_M.gguf --port 8080

# 2. 指向本地
export RPGBAR_LLM_BASE_URL="http://127.0.0.1:8080/v1"
export RPGBAR_LLM_MODEL="qwen3-8b"
export RPGBAR_LLM_API_KEY="none"
```

发布时由玩家用自己算力跑本地 DM 即走这条路。

### 7.3 脚本化兜底

不配 key 时，DM 自动降级为「脚本化兜底」：用剧本原文 + 出口/检定提示生成旁白。玩法完整可玩，适合离线演示。

## 八、技术实现细节

### 8.1 RAG 检索

- 分词：`jieba`
- 打分：`rank-bm25`（BM25Okapi）
- 每个场景的可检索文本 = 标题 + 地点 + 关键词 + NPC 名 + 公开文本
- 检索结果：当前场景永远排第一，其余按 BM25 分数取 top-k，注入 DM 上下文

### 8.2 剧情状态机

- `GameState` 持有：玩家、flag 集合、当前场景、历史、回合数
- 出口条件：`condition` 为空恒可用，否则要求对应 flag 在集合中
- 服务端权威：客户端只收到状态快照（`state` 消息），不直接改状态

### 8.3 服务端权威骰子

- `dice.roll_check(skill, dc)`：d20 检定，返回 `{skill, dc, roll, success}`
- 支持 `dice.seed(n)` 设种子，便于测试复现

### 8.4 护栏：LLM 提案 + 服务端校验

LLM 返回 JSON（`narration` / `move_to` / `set_flags`），服务端：

- `move_to` 必须是当前场景列出的出口、且条件满足，才推进
- `set_flags` 必须落在 `FLAG_WHITELIST` 内，才生效
- 骰子结果由服务端投，LLM 不得编造

## 十、打包发布（发给朋友）

### 10.1 打包成 exe

```bash
pip install pyinstaller
pyinstaller --name RPGBarServer --onedir --noconfirm --clean \
  --add-data "web;web" \
  --add-data "scripts;scripts" \
  --add-data "config.example.json;." \
  --collect-all jieba \
  --exclude-module uvloop --exclude-module watchfiles \
  run_server.py
```

产物在 `dist/RPGBarServer/`，压缩成 zip 即可发送：

```bash
python -c "import shutil; shutil.make_archive('RPGBarServer','zip',root_dir='dist',base_dir='RPGBarServer')"
```

### 10.2 朋友怎么用

1. 解压 zip，双击 `RPGBarServer.exe`（首次可能需点「仍要运行」+ 防火墙「允许访问」）。
2. 黑色窗口里记下「局域网访问」地址（`http://192.168.x.x:8000`）。
3. 主机浏览器打开 `http://127.0.0.1:8000` 建房，把房号（5 位码）发给朋友。
4. 朋友浏览器打开「局域网访问」地址，填同一房号加入。

> 打包后的可写配置 `config.json` 放在 exe 旁边；只读资源（web/scripts/剧本）在 `_internal` 里。
> 异地联机需内网穿透（ZeroTier / Tailscale / cpolar / frp）。

### 10.3 DM 下沉本地（正式版）

发布时由玩家本地跑 llama.cpp 模型（见 §7.2），算力全在玩家机器。

## 十二、已知局限（当前实现）

1. **游戏状态在内存中**：服务器重启即丢失房间与进度，未做持久化（后续可加 JSON/SQLite 存档）。这也意味着「中途加入」只在服务器不重启的前提下有效。
2. **未做鉴权/防滥用**：房间码公开可猜，无身份校验（demo 阶段可接受）。
3. **跨网络需自配穿透**：不同局域网的朋友联机需要 frp/cpolar 或云主机。
4. **回顾不含骰子细节**：新玩家能看到「做了什么」和「拿到了什么线索」，但不会重放此前的具体骰点；配了 LLM 时可由模型在旁白里概述。
5. **断线重连即视为中途加入**：玩家掉线后重新加入会走一遍补课流程（信息正确，只是会多出一段带入旁白）。

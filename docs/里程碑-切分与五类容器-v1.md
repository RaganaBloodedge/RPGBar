## 2. 六个真 bug（都会让结果"看起来正常但其实是错的"）

1. **系统代理 502**：Windows 代理被 httpx 的 `trust_env` 带进来，把发往 `127.0.0.1:8080` 的请求接走并返回 502，llama-server 日志里一条请求都没有。上一版 62% 的块因此静默回落词表 —— "LLM 主判"从未真正发生。
2. **书签同页只按页码切**：COC 第 77 页挂 4 个书签，四节各自整页切一遍 → 三胞胎。改为书签落点 y + 页内阅读顺序行号。
3. **属性表 y 跨页比较**：`_pos_index` 漏了页码，26 张怪物属性表全挂到第一节上。
4. **多窗口行号没加偏移**：第二个窗口之后的条目起点全变成 0 被去重丢掉 → 怪物图鉴 32 页压成一条 2255 行巨块。
5. **自检用正则改模型判的边界**：技能列表被当"逐行切"、怪物小标题被切成独立条目。LLM 路径下自检改为只统计不修。
6. **一次性抽取 schema 太大**：实体+字段一起问，4B 输出近一半截断（34 分钟、判废 48%）。拆两段后 5 分钟、判废大幅下降。

> 另有一次人为事故：用 PowerShell 的 `Get-Content|Set-Content` 改源码，把 `nodes.py`、`state.py`、`containers.py` 的编码搞坏（前两个无备份，按新设计重写）。**结论：源码只用文件工具改。**

## 3. 设计定论（这一版不再讨论的）

1. **判定权只归模型**：这一节是什么类、条目边界在哪、这块是不是示例、规则子类怎么分、世界观摘要写什么、谁和谁什么关系 —— 全部问模型。
2. **规则只做几何与验收**：阅读顺序、页内锚点、表格网格、原文偏移；验收 = 行号合法递增 / 标题逐字来自行首 / 按行拼回无损 / 引文逐字回原文 / 端点必须在原文出现。**任何一条不过就重问，绝不回落词表。**
3. **几何证据可以否决语义判断**：一节里有 ≥2 张"属性|平均|掷骰"表 → 按 NPC 的成员定义切（表就在那儿，是事实不是判断）。
4. **拼装归规则**：技能/物品/NPC 档案从已有 `fact/field` 投影；流程图由判定步骤拼，不让模型画。
5. **canonical 单独问**：与类别混在一起问，4B 一律回 true。拆成"这段是不是用具体人物把规则演一遍"的二选一，才答得对。
6. **切分按节缓存**：缓存名带 `SEG_VERSION`，逻辑一改自动失效；重跑只补没切过的节（170 节里 169 节命中，split 57 分钟 → 67 秒）。

## 4. 关于「这算不算 Agent」的结论（重要）

**不算。** 它是 agentic workflow：有目标、感知、工具、状态、反馈，但**下一步做什么由我们画的固定边决定**，模型只在节点内回答"这个判断对不对"。

不做的理由：编译器的正确性是硬指标（深潜者 CON 唯一、三胞胎为零），把流程交给 4B 自主决定会出现"反复重切同一节 / 把看起来干净当通过 / 失败时换省事策略"。**确定性骨架 + 局部让模型判**是这类编译器该有的形状。

但按用户的"标准 Agent"目标，缺三样（下一步可补）：
1. **Planner**：输入当前状态+失败原因，从封闭动作集里选下一步（重新切/缩窗/合并/换类/标争议/收尾）；
2. **工具注册表**：把现有函数包成带 schema 与验收的工具（`compiler/lc/tools.py` 已有雏形，但那是给外部 Agent 用的）；
3. **经验记忆**：失败原因跨节复用（现在只有本节重试）。

建议形态：**正常路径走固定边，失败路径交给 planner**。

## 5. 自检与自纠错（下一步的主线，不依赖 Agent）

用户要"切错了能自己发现并纠正"。设计成固定循环：

- **A 结构自检（确定性、免费）**：块长异常（<15 字 / >本节中位数×4）、标题是句中片段（以"的/在/如果"开头或以"，；："结尾）、标题是表格碎片（`-9`、`$5M+`、`125-164`、`⊙ 姓名`）、同节标题近似重复、属性表/表格游离、**覆盖不变量**（每行恰好属于一个块）。
- **B 只对可疑块问模型（带邻居）**：动作集封闭为 `ok / merge_prev / merge_next / split_after_line=N`；护栏：切点行真实存在、切完无损、merge 不能吞掉完整条目。
- **C 修复→复检循环**：每步写 `meta.repair_history` 与 trace；预算用完就停在"仍有可疑"并报告，不假装干净。
- **D 成员身份验收（可证伪）**：每块要么有"新条目头"（标题逐字来自首行），要么是"纯续写"（标题为（续N））；表格块必须 `is_table`。

现有 `selfcheck.py` 是雏形，但它是正则重切，在 LLM 路径下会跟模型打架（已禁用）。

## 6. 关于「其他 150」与「大类要不要动态扩展」

**先纠正数字**：`rule_subtype.rules` 那一列记的是"每批模型分到该组的条数之和"，且"其他"子类行在一次重建中没有落表；库里 `rs:其他` 实际只有 15 条 entry，并不存在 150 条的"其他"大类。

**真实问题**（抽样证据）：

```
p28 '表Ⅰ：伤害加值和体格表' | 力量+体型 伤害加值 体格 2-64 65-84 …
p28 '体质'                | 0：死亡。1：病弱。15：健康堪忧…
p32 '信用评级'            | 信用评级：０－１５ 本职技能点：教育×２…
p38 '$5M+' / '-9'         | 表格单元格
```
未分类 110 块也是同类：`〔他们照做了…〕`（跑团实录）、`新版说明`（版本变更）、`125-164`（页码区间）、`步骤`（孤立小标题）、`⊙ 头像`（建卡小节）。

**结论**：缺的不是第 6 大类，而是
1. **表格/参考数据没有出口**（`table`，判据是几何的：is_table / 一行一值 / 无句读 / 有表头；表格块占比超阈值才启用）；
2. **元信息没有出口**（`meta`，判据是位置：卷首卷尾、讲的是这本书自己）；
3. **分类单位错了**：拿"块"判五类，而块里混着表头+行、标题+正文；正确单位是**成员**。

**子类必须动态**（已在做，13 个并行子类，名字从章+标题长出来）；**大类不让模型自由发明**（路由、验收、报告都围绕五个出口；4B 每本书发明一套会漂移且无法验收）。扩展位由**结构证据触发**，不由模型命名。

## 13. DM 接入实测（2026-10-24 第二轮）

把五类容器接成 DM 工具（`server/kb_tools.py`：`kb_lookup` / `kb_lore` + 按剧本取库），
四局实跑（`scripts/play_kb.py`）暴露出四类问题，都已修：

| 问题 | 证据（玩家那局的原文） | 修法 |
|---|---|---|
| 工具报错被念成旁白 | 问「我现在在哪儿」→ DM 答「当前场景没有检定 侦查，无法进行相关检定」 | 护栏加"复述工具报错"判据 + 丢弃后**重试一次**；提示词写明"error 是给你看的，不要写进旁白" |
| 拿规则书配无关模组 | 蛇王墓 + CoC 规则书库，DM 讲出"深潜者是蛇王的直属下属" | **按剧本取库**：剧本 JSON 声明 `"kb"`，或 `data/kb/<剧本名>/kb.sqlite`；找不到就没有库工具（不再全局挑最新库） |
| 4B 不主动查库 | 同提示词，一局调了 `kb_lookup/kb_lore`，另一局一次没调 | **确定性注入**：玩家话里出现库里的名字，就把条目直接放进上下文（`kb_brief`），不赌模型自觉 |
| 只会判定、不引导 | 旁白只有一句判定性回答 | 提示词加"旁白要有引导"（一个可感知细节 + 一个可动手的钩子）与"问方位直接用【当前场景】回答、不要投骰" |

修后实测（蛇王墓，无库）：
- 「我现在在哪儿」→ 直接给出"地点：蛇王墓入口 · 山腰崖下"和门/泥水/风灯的具体细节，没有一次投骰；
- 带 `"kb": "coc7e-v3"` 的探针剧本：「手枪伤害」→ 1D6+1（燧发手枪，p390）；「深潜者多强」→ 各项属性 65+、体格/力量、水族遗产（NPC 卡）。

仍存在的：① 4B 会把上下文小标题（"地点：…"）念进旁白；② 上一轮描写被逐字复用（护栏只拦"整段逐字相同"）；③ 同一条规则两次抽出的判定步骤数不稳定（4 ↔ 1）。

## 14. 第一期落地：世界层（世界记忆）

按用户拍板的架构：**KB 只读事实层 / 世界层每剧本独立库 / 叙事流水**。
新增 `server/world.py`，一局一个库：`data/worlds/<剧本名>/<房间号>.sqlite`。

| 表 | 作用 |
|---|---|
| `meta/pointer` | 这局用的是哪个剧本/知识库、当前场景、第几轮、第几天、昼夜 |
| `scene` | 地点（seed 来自剧本，generated 来自游玩） |
| `entity` | 现场有什么（object/npc/creature/clue），布景必须 `declare` 才存在 |
| `thread` | 还没收束的线索 |
| `entity_fact` / `advance` | 实体属性、时间推进（分钟 → 昼夜 → 天，跨昼夜广播事件） |

每轮注入 DM 两段：`【现场】`（肯定式列举：原文描述 + 已登记的东西）与`【进度】`（第几轮/第几天/未收束线索/去过的地方）。

### 「打开门但没有门」的实测

| 版本 | 玩家说 | DM 回答 |
|---|---|---|
| 没有世界层 | 我推开门走出去 | 描写石壁、气氛，**顺着他演** |
| 加【现场】 | 我推开门走出去 | 「这里没有门。」✅ |
| 加 few-shot 后 | 我取下青铜灯，看灯座有没有刻字 | 「这里没有青铜灯」❌（把原文写着的灯也否认了） |
| **加确定性指代校验** | 同上 | 「这里没有灯座，也没有刻字。青铜灯早已锈蚀…」✅（物件存在、细节不存在） |

结论：**4B 分不清"玩家提到"和"这里存在"，而且 few-shot 会让它过度否认。**
可靠的做法是服务端做机械比对：`World.unresolved()` 用 jieba 抽名词，与
「现场实体 + 场景原文 + KB 名字」比对，把未落地的名词直接标进上下文
（`【未落地的指代】`），让 DM 只负责表达。

# 长模拟测试方案（设计稿，2026-10-22）

> 目标：一条命令从头到尾推完整个剧本，记录**每一次模型生成的速度**与**内容的正确性**，
> 产物可复用、可对比，评判标准固定 —— 以后每次改进（提示词、后端、上下文预算）跑一遍就知道变好还是变坏。

## 0. 原则

1. **骰子不设种子**（2026-10-22 定案）：跨房间共用随机流算特性。⇒ 所有断言必须**对骰子结果不敏感**：
   「说服成功」和「说服失败」都是合法路径，断言只看「有没有投骰、旁白有没有跟上结果」。
2. **记录在服务端，评判在测试端**：游戏服务器只负责把遥测吐全；对错与分数由测试脚本离线算，
   服务器不为测试加分支。
3. **两层评判**：机械对错用确定性断言（每次必跑、非黑即白）；内容好坏用固定 rubric 评分
  （LLM 评审 + 人工抽查）。不混在一起 —— 断言挂了就是挂了，评分可以慢慢看。

## 1. 现状盘点

**已有（直接复用）：**
- WebSocket 事件流：`narration` / `dice` / `thinking` / `agent_note` / `state` —— 内容与机制结果的原始记录。
- `AgentResult.steps`：每轮的工具调用 trace（tool / args / result），测试断言现成的依据。
- 轮级耗时日志：`一轮 dm 45.1s（NPC 预备 x.x s · 生成 N 次 · 工具 …）` —— 但只进 stdout，不是数据。
- 剧情档案 `data/chronicle-<room>.jsonl`：每轮「已发生事实」落盘。
- 探针：`scripts/_bench_round.py`（计时）、`scripts/_probe_events.py`（消息流水）—— 长测机器人的雏形。

**缺的（本方案要补）：**
- ❌ **生成级遥测**：`llm.py` 调 `engine.generate()` 前后只算墙钟，**prompt tokens / 生成 tokens / tok/s**
  都没记。引擎是我们自己的 C 库，返回 JSON 里加字段即可拿到；拿不到就先用「墙钟 + 字符数」顶。
- ❌ 事件流没有结构化留档成「一次测试运行」的产物。
- ❌ 没有全剧本通关的行动剧本（playbook），也没有评判脚本。

## 2. 三个组件

### 2.1 玩家机器人 `scripts/simtest.py`

- 走 WebSocket 开房 → `start` → 按 **playbook** 逐条发动作 → 每步等本轮结束 → 收尾。
- **playbook**（`scripts/simtest_playbook_totsk_l1.json`）：人工设计的一条「标准通关路径」，
  每个场景 1–2 个动作，覆盖全部 9 场景、12 flags、各检定与出口、若干次建议请求、
  若干条**越界动作**（要被拒绝的那种）和**元问题**（要被分流的那种）。
  动作条目带**期望**字段：`{"action": "...", "expect": {"roll": "investigate_gate", "flag": "gate_opened"}}`
  —— 断言素材直接长在剧本里，改剧本就改测试。
- 模式：`--full`（全剧本通关）与 `--quick`（固定 3 场景 5 轮，日常回归用）。

### 2.2 遥测钩子 `server/telemetry.py`（新增，服务器只加不改逻辑）

- 一个进程级 sink：`llm.py` 每次 `generate()` 前后记一条 ——
  `{"slot", "backend", "model", "prompt_chars", "gen_chars", "gen_tokens"(引擎给就记), "elapsed_s", "tok_s", "ts", "room"}`。
- `main.py` 每轮收尾把 `AgentResult.steps`（工具 trace）+ 轮级摘要追加一条 round 记录。
- 输出两路：`runs/<run_id>/telemetry.jsonl` + `events.jsonl`（现有 WS 事件原样落）。
- **正常运行也开着**（开销可忽略），测试只是给 run 起个名字：`run_id = 传入的 label 或时间戳`。

### 2.3 评审脚本 `scripts/simreport.py`

对一次 run 产物（或 `--diff A B` 对比两次）产出报告：

**A. 确定性断言（每次必跑，PASS/FAIL）**
1. 机制：每条 `dice` 事件的检定 id ∈ 剧本 checks，且投骰前动作原话命中 keywords（复用门逻辑反向核对）；
2. 越界：越界 playbook 条目之后的旁白**不得**命中越界成功词表；
3. 分流：元问题 playbook 条目 0 生成、有 `agent_note(source=system)`；
4. 推进：场景迁移只经合法出口；flags 单调不回退（除非剧本允许）；
5. 健全性：每轮 narration 非空、`stopped ∈ {final}`、无 `max_steps`/`error`；
6. 建议：每条建议 ≥8 字、不含出口 label 原文、（候选充足时）含触发词。

**B. 内容质量 rubric（固定分值，LLM 评审 prompt 固定、温度 0）**

每个叙事轮按 5 维打 0–2 分（满分 10）：
| 维度 | 0 分 | 2 分 |
|---|---|---|
| 局势贴合 | 旁白与当前场景/近期事实脱节 | 明确引用场景要素或刚发生的事 |
| 前后一致 | 与档案矛盾（人/物/状态） | 无矛盾，且延续既有线索 |
| 语言质量 | 大段复读/模板腔 | 流畅有细节，无跨轮复读 |
| 骰子呼应 | 旁白与骰点结果相悖 | 旁白明确体现成功/失败 |
| NPC 一致 | NPC 性格/立场跳变 | 符合人物卡设定 |

advisor 建议另有 3 维（成句性 / 贴合局势 / 触发词可达），越界拒绝感单列 1 维。
评审模型**固定**（配置里写死用哪个模型），换评审模型 = 换标尺，报告里必须标注。
人工抽查：每个 run 随机抽 3 轮对照 LLM 分数，偏差大就修 prompt 不改 rubric。

### 3. 产物目录（一次 run = 一个目录，自包含）

```
runs/
  2026-10-22T1215_full_4b78591/
    manifest.json      # git commit、config 快照、模型路径+大小、剧本 hash、耗时
    events.jsonl       # 全部 WS 事件（含 dice、agent_note、state 快照）
    telemetry.jsonl    # 生成级遥测 + 轮级摘要（工具 trace）
    assertions.json    # A 层逐条 PASS/FAIL
    scores.json        # B 层逐轮逐维评分
    report.md          # 汇总：通过率、P50/P95 延迟、tok/s、总分
```

对比就是 `simreport.py --diff runs/A runs/B`：延迟表逐槽位对比、断言差异、分数差异。

### 4. 关键指标（进 report.md 的固定段落）

- 速度：dm / assistant / advisor 三槽位各自的**冷启动**、**热态 P50 / P95**、tok/s（或 chars/s）；
- 效率：每轮生成次数（tools 循环深度）、prompt 字符量分布（对着路线③「上下文预算」看效果）；
- 正确性：断言通过率 + rubric 总分与各维均分。

### 5. 分期实施

| 期 | 内容 | 量级 |
|---|---|---|
| P0 | telemetry 钩子 + events 落盘 + manifest | 半天 |
| P1 | simtest.py（机器人）+ playbook 全剧本 + A 层断言 | 一天 |
| P2 | simreport.py 汇总 + --diff | 半天 |
| P3 | B 层 rubric 评审（选定评审模型 + 固定 prompt） | 半天 + 调标 |

先做 P0+P1 跑出第一个基线（`baseline_full_4b78591`），以后任何改动都拿它对照。

### 6. 边界与风险

- **非确定性**：同一 playbook 跑两次内容不会一样 —— 内容评审看「分数量级与维度趋势」，不逐字比；
  断言层必须设计成骰子结果无关（原则 1）。
- **playbook 会过时**：剧本改动要同步 playbook，把这个写进改剧本的检查清单。
- **跑一次全剧本 ≈ 20–40 min**（DM ~20–45 s/轮 × ~15 轮 + 建议若干）—— 所以日常用 `--quick`，
  发版/大改前跑 `--full`。
- 遥测对正常玩家开销：每条生成记录一次 `time.time()` + append 文件，可忽略。
